
# DynamicBuilderHelper 触发源梳理

> 文件路径：`ad-oracle-service/src/main/java/com/kuaishou/ad/oracle/service/helper/dynamic/DynamicBuilderHelper.java`
>
> 核心入口方法：
>
> - **`handleUnitSafely`** — 补充单元
> - **`handleCreativeSafely`** — 补充创意

---

## 一、审核通过触发

监听审核状态变更事件，审核通过后触发动态补充。

| Consumer 类                       | Kafka Topic                   | Event Type                               | sourceType                 | 调用入口                 |
| --------------------------------- | ----------------------------- | ---------------------------------------- | -------------------------- | ------------------------ |
| `DynamicSmartUnitConsumer`      | `adcore_event_unit`         | `UNIT_PUT_STATUS_CHANGE`               | `UNIT_EVENT_TRIGGER`     | `handleUnitSafely`     |
| `DynamicSmartCreativeConsumer`  | `adcore_event_adv_creative` | `ADV_CREATIVE_EFFECTIVE_STATUS_CHANGE` | `CREATIVE_EVENT_TRIGGER` | `handleCreativeSafely` |
| `DynamicCustomCreativeConsumer` | `adcore_event_creative`     | `CREATIVE_EFFECTIVE_STATUS_CHANGE`     | `CREATIVE_EVENT_TRIGGER` | `handleCreativeSafely` |

**说明：** 单元/创意审核通过（含智能创意包、自定义创意）→ Kafka 状态变更事件 → Consumer 过滤有效审核状态 → 触发补充基建。

---

## 二、拒审触发

分两条链路：普通拒审补充 和 UAA AI 拒审修复。

### 2.1 普通拒审补充

| 类                                                | Topic / 来源                  | Event Type                                       | sourceType                      | 调用入口                 |
| ------------------------------------------------- | ----------------------------- | ------------------------------------------------ | ------------------------------- | ------------------------ |
| `DynamicRejectReviewBuildCreativeConsumer`      | `adcore_event_creative`     | `CREATIVE_EFFECTIVE_STATUS_CHANGE`（拒审）     | `REJECT_REVIEW_BUILD_TRIGGER` | `handleCreativeSafely` |
| `DynamicRejectReviewBuildSmartCreativeConsumer` | `adcore_event_adv_creative` | `ADV_CREATIVE_EFFECTIVE_STATUS_CHANGE`（拒审） | `REJECT_REVIEW_BUILD_TRIGGER` | `handleCreativeSafely` |
| `DynamicRejectReviewHelper`                     | Consumer 窗口聚合后调用       | —                                               | `REJECT_REVIEW_BUILD_TRIGGER` | `handleCreativeSafely` |

**说明：** Consumer 对同一单元的拒审事件做窗口聚合，通过 `DynamicBuildContext.getBuildCreativeNum()` 控制本次补充的创意数量（不超过拒审数）。

### 2.2 UAA AI 拒审修复

| 类                                 | 来源            | sourceType                              | 调用入口                 |
| ---------------------------------- | --------------- | --------------------------------------- | ------------------------ |
| `DynamicRejectRepairBuildHelper` | UAA AI 修复链路 | `DYNAMIC_REJECT_REPAIR_BUILD_TRIGGER` | `handleCreativeSafely` |

**说明：** 先删除所有被拒审的子创意，再用 AI 修复后的素材一次性批量补建（`creativeNumParam = needBuildPhotos.size()`），绕过大盘白名单、余额、消耗等常规校验，使用独立放量开关。

## 三、直播触发

### 3.1 实时事件触发

| Consumer 类                                    | Kafka Topic               | Event Type                          | sourceType                             | 调用入口                 |
| ---------------------------------------------- | ------------------------- | ----------------------------------- | -------------------------------------- | ------------------------ |
| `DynamicSmartLiveUnitCreateFastConsumer`     | `adcore_event_campaign` | `CAMPAIGN_CREATE`（直播推广计划） | `LIVE_CAMPAIGN_CREATE_EVENT_TRIGGER` | `handleUnitSafely`     |
| `DynamicSmartLiveCreativeCreateFastConsumer` | `adcore_event_unit`     | `UNIT_CREATE`（直播自定义单元）   | `LIVE_UNIT_CREATE_EVENT_TRIGGER`     | `handleCreativeSafely` |

### 3.2 直播补偿任务（Consumer 失败重试）

| Task 类                | 数据来源               | sourceType                          | 调用入口                 |
| ---------------------- | ---------------------- | ----------------------------------- | ------------------------ |
| `LiveCompensateTask` | Redis 直播失败补偿队列 | `LIVE_CAMPAIGN_CREATE_EVENT_TASK` | `handleUnitSafely`     |
| `LiveCompensateTask` | Redis 直播失败补偿队列 | `LIVE_UNIT_CREATE_EVENT_TASK`     | `handleCreativeSafely` |

**说明：** 实时 Consumer 触发失败时，将失败的计划/单元写入 Redis，由补偿任务异步重试。若重试后仍未处理成功，通过 `DynamicRedisHelper.setNeedRetryCampaign/setNeedRetryUnit` 标记等待下次补偿。

### 3.3 直播高亮素材（平行链路）

| Helper 类                    | 触发方                       | sourceType                           |
| ---------------------------- | ---------------------------- | ------------------------------------ |
| `LiveHighPhotoBuildHelper` | `AdOracleService` RPC 接口 | `LIVE_PHOTO_PRODUCE_EVENT_TRIGGER` |

**说明：** 直播产出高亮素材时通知 Oracle，内部复用 `DynamicBuilderHelper.getDynamicBuildLevelInfo` 等工具方法，有独立的 `handleCreativeSafely` 实现。

## 四、新素材触发

| Helper 类               | 触发方                       | sourceType                          |
| ----------------------- | ---------------------------- | ----------------------------------- |
| `NewPhotoBuildHelper` | `AdOracleService` RPC 接口 | `NEW_PHOTO_PRODUCE_EVENT_TRIGGER` |

**说明：** 用户上传新素材或 AIGC 生产出新素材时，业务侧通知 Oracle，为所有符合条件的单元补充创意。该 Helper 有独立实现，复用 `DynamicBuilderHelper` 的部分查询方法。

## 六、消耗计费触发（Databus Binlog）

| Resolver 类                    | 数据来源                            | sourceType               | 调用入口                                        |
| ------------------------------ | ----------------------------------- | ------------------------ | ----------------------------------------------- |
| `DynamicChargeResolver`      | Databus MySQL Binlog`ROWS_INSERT` | `CHARGE_TRIGGER`       | `handleCreativeSafely` / `handleUnitSafely` |
| `DynamicOrderChargeResolver` | Databus MySQL Binlog`ROWS_INSERT` | `ORDER_CHARGE_TRIGGER` | `handleCreativeSafely` / `handleUnitSafely` |

**说明：** 每一笔扣费记录写入 MySQL → Databus binlog → Resolver 拦截 → 判断该账户/计划有单元则补创意，无单元则补单元。为实时最快速的补充触发时机。

## 九、AdOracleTaskApplication 定时任务

### 9.1 调用 DynamicBuilderHelper 的基建任务

| Task 类                   | 数据来源                                                | sourceType                                                            | 调用入口                                        | 说明                             |
| ------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------- | ----------------------------------------------- | -------------------------------- |
| `DynamicBuildTask`      | Redis`dynamicUnitKey(accountId)` 队列（10万分片扫描） | `TASK_TRIGGER`                                                      | `handleCreativeSafely` / `handleUnitSafely` | 全量兜底扫描，速率 300/s，50线程 |
| `DynamicCompensateTask` | Redis`cam_cost_top_in_acc_s{accountId}` 消耗计划列表  | `CAMPAIGN_COST_COMPENSATE_TRIGGER`                                  | `handleUnitSafely`                            | 针对有消耗账户的计划做补偿基建   |
| `LiveCompensateTask`    | Redis 直播失败补偿队列                                  | `LIVE_CAMPAIGN_CREATE_EVENT_TASK` / `LIVE_UNIT_CREATE_EVENT_TASK` | `handleUnitSafely` / `handleCreativeSafely` | 直播 Consumer 失败补偿重试       |

### 9.2 关停策略任务（不经过 DynamicBuilderHelper）

> 关停任务独立于基建体系，直接调用 `smartSAO.pauseUnit`，数据来源均为 Hive 离线计算结果。

| Task 类                             | 策略说明                       | 数据来源                                 | 关键白名单/开关                                                                                                          |
| ----------------------------------- | ------------------------------ | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `OverCostUnitPauseTask`           | **超成本单元关停**       | Hive`overCostUnitPauseSQL`（昨日数据） | `OverCostTaskPauseSwitch`，保留最后一个单元不关                                                                        |
| `ZeroCostUnitPauseTask`           | **零消耗/空耗单元关停**  | Hive`zeroCostUnitPauseSQL`（昨日数据） | `pauseUnitOracleSwitch`，今日0点起消耗 > 0 的单元跳过，每计划最多关 3 个（`CAMPAIGN_LIMIT`），按 campaignId 尾号放量 |
| `OverCostSmartCreativePauseTask`  | **超成本智能创意关停**   | Hive                                     | —                                                                                                                       |
| `OverCostCustomCreativePauseTask` | **超成本自定义创意关停** | Hive                                     | —                                                                                                                       |
| `OverCostCampaignPauseTask`       | **超成本计划关停**       | Hive                                     | —                                                                                                                       |
| `EmptyCostCampaignPauseTask`      | **空耗计划关停**         | Hive                                     | —                                                                                                                       |

## 触发链路总览

```
外部事件
  │
  ├─ Kafka: adcore_event_campaign (CAMPAIGN_CREATE)
  │     ├─ DynamicSmartUnitCreateFastConsumer        → CAMPAIGN_CREATE_EVENT_TRIGGER     → handleUnitSafely
  │     ├─ DynamicSmartLiveUnitCreateFastConsumer    → LIVE_CAMPAIGN_CREATE_EVENT_TRIGGER → handleUnitSafely  [直播]
  │     └─ DynamicPeriodicNightSmartUnitCreateConsumer → PERIODIC_DELIVERY_NIGHT          → handleUnitSafely  [夜间稳投]
  │
  ├─ Kafka: adcore_event_unit (UNIT_CREATE / UNIT_PUT_STATUS_CHANGE)
  │     ├─ DynamicSmartUnitConsumer                      → UNIT_EVENT_TRIGGER                    → handleUnitSafely    [审核]
  │     ├─ DynamicSmartCreativeCreateFastConsumer        → UNIT_CREATE_EVENT_TRIGGER              → handleCreativeSafely
  │     ├─ DynamicSmartLiveCreativeCreateFastConsumer    → LIVE_UNIT_CREATE_EVENT_TRIGGER         → handleCreativeSafely [直播]
  │     ├─ DynamicFirstCreativeCreateByUnitConsumer      → COMMON_UNIT_FIRST_CREATE_EVENT_TRIGGER → handleCreativeSafely [素材优选首创]
  │     └─ DynamicPeriodicNightSmartCreativeCreateConsumer → PERIODIC_DELIVERY_NIGHT              → handleCreativeSafely [夜间稳投]
  │
  ├─ Kafka: adcore_event_creative / adcore_event_adv_creative
  │     ├─ DynamicSmartCreativeConsumer / DynamicCustomCreativeConsumer
  │     │     └─ CREATIVE_EVENT_TRIGGER → handleCreativeSafely  [审核通过]
  │     ├─ DynamicRejectReviewBuildCreativeConsumer
  │     │     └─ REJECT_REVIEW_BUILD_TRIGGER → handleCreativeSafely  [拒审]
  │     └─ DynamicRejectReviewBuildSmartCreativeConsumer
  │           └─ REJECT_REVIEW_BUILD_TRIGGER → handleCreativeSafely  [拒审]
  │
  ├─ Databus Binlog (MySQL ROWS_INSERT 扣费记录)
  │     ├─ DynamicChargeResolver       → CHARGE_TRIGGER       → handleCreativeSafely / handleUnitSafely
  │     └─ DynamicOrderChargeResolver  → ORDER_CHARGE_TRIGGER → handleCreativeSafely / handleUnitSafely
  │
  ├─ RPC 接口 (AdOracleService)
  │     ├─ NewPhotoBuildHelper         → NEW_PHOTO_PRODUCE_EVENT_TRIGGER    [新素材产出]
  │     └─ LiveHighPhotoBuildHelper    → LIVE_PHOTO_PRODUCE_EVENT_TRIGGER   [直播高亮素材]
  │
  ├─ Helper 内部（非 Consumer 直接调用）
  │     ├─ DynamicRejectReviewHelper       → REJECT_REVIEW_BUILD_TRIGGER         → handleCreativeSafely  [拒审窗口聚合]
  │     └─ DynamicRejectRepairBuildHelper  → DYNAMIC_REJECT_REPAIR_BUILD_TRIGGER → handleCreativeSafely  [UAA AI修复]
  │
  ├─ 算法 Agent Consumer
  │     ├─ UaxAgentAlgoBuildConsumer   → ALGO_UAL_AGENT / ALGO_UAA_AGENT → handleCreativeSafely / handleUnitSafely
  │     └─ AuaxAgentAlgoBuildConsumer  → ALGO_AUAX_AGENT / COMMERCE_ALGO → handleCreativeSafely / handleUnitSafely
  │
  └─ AdOracleTaskApplication 定时任务
        │
        ├─ 基建任务（调用 DynamicBuilderHelper）
        │     ├─ DynamicBuildTask         → TASK_TRIGGER                   → handleCreativeSafely / handleUnitSafely  [Redis扫描兜底]
        │     ├─ DynamicCompensateTask    → CAMPAIGN_COST_COMPENSATE_TRIGGER → handleUnitSafely                       [消耗补偿]
        │     └─ LiveCompensateTask       → LIVE_*_TASK                    → handleUnitSafely / handleCreativeSafely   [直播补偿]
        │
        └─ 关停策略任务（直接调用 smartSAO.pauseUnit，不经过 DynamicBuilderHelper）
              ├─ OverCostUnitPauseTask         超成本单元关停      (Hive离线)
              ├─ ZeroCostUnitPauseTask         零消耗/空耗单元关停  (Hive离线 + 今日实时消耗二次校验)
              ├─ OverCostSmartCreativePauseTask  超成本智能创意关停
              ├─ OverCostCustomCreativePauseTask 超成本自定义创意关停
              ├─ OverCostCampaignPauseTask      超成本计划关停
              └─ EmptyCostCampaignPauseTask     空耗计划关停
```

### 注意事项

1. **关停与基建解耦**：关停任务（`OverCostUnitPauseTask`、`ZeroCostUnitPauseTask` 等）**不经过** `DynamicBuilderHelper`，直接调用 `smartSAO.pauseUnit`，属于独立的策略体系。
2. **拒审两条链路区别**：

   - 普通拒审 (`REJECT_REVIEW_BUILD_TRIGGER`)：窗口聚合后补充，受大盘白名单、余额、quota 等常规约束。
   - UAA AI 修复 (`DYNAMIC_REJECT_REPAIR_BUILD_TRIGGER`)：先删后建净增 0，绕过大盘白名单和消耗/余额/预算校验，使用独立放量开关。
3. **平行 Helper**：`NewPhotoBuildHelper`、`LiveHighPhotoBuildHelper` 是与 `DynamicBuilderHelper` 平行的帮助类，有各自的 `handleCreativeSafely` 实现，但会复用 `DynamicBuilderHelper` 的工具方法（如 `getDynamicBuildLevelInfo`、`checkUnitFrequency`）。
4. **M2 防循环**：`M2UnitBuildConsumer` 消费 `UAX_DYNAMIC_UNIT_BUILD_TOPIC`，该 topic 在 `DynamicBuilderHelper.handleUnit` 中对所有非 `M2_SOFT_UNIT_BUILD` 来源都会下发，通过 sourceType 判断避免无限循环。
