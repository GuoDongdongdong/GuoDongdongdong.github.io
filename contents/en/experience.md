#### 1. Conversational Ad Creation — Ad Creation Agent --- Sep 2026 - Oct 2026

- **Background:** Traditional ad creation required advertisers to manually complete product selection, material selection and bidding across multiple platforms — cumbersome and high-barrier.
- **Goal:** Build an Ad Creation Agent that provides conversational ad creation via the existing customer-facing Agent (Cili Qingsong), letting advertisers complete ad creation through natural-language, multi-turn interaction. Qingsong handles intent understanding, slot extraction and clarification; the Ad Creation Agent handles permission validation, product selection and asset building.
- **Responsibilities (challenge + approach):**
  - **Co-designed the Qingsong AgentTask runtime**: conversational creation is the first long-running task combining multi-turn and async interaction — a task may span multiple user requests and its creation result returns asynchronously, requiring context persistence and recovery. Approach: event-driven, Task state machine (aligned with A2A TaskState), AgentTask persistence, Checkpoint context persistence, and Artifact separation.
  - **Product selection**: the original optimization relied only on posterior-spend random recall, without using content information or platform user profiles. Approach: built an LLM-based selection pipeline — reverse-inferred 11 short-drama feature weights from top-performing dramas, added a trending-hit RAG knowledge base (recall by actor / plot / theme) to mitigate knowledge hallucination, scored text (title / synopsis / cast / ASR / category) and visual (cover + first-episode keyframes, with SSIM frame extraction filtering ~60% duplicate frames) in separate stages, then fused 60-day spend and other posterior data with a user-profile matching factor, and finally ordered by model score (force) into system optimization.
  - **Parameter validation & conflict resolution**: account status, industry, authorization and field dependencies (Kuaishou account > product (book/drama) > conversion goal > ROI) are all hard constraints — one validation mistake may cause illegal creation, cross-account or cross-product issues. Approach: a deterministic rule engine handles validation and conflict resolution (not decided by the model); the LLM only assists in spotting possible conflicts; customer-specified values take priority, replacements are shown explicitly, and model output is never trusted without passing the rules.
  - **Security & write safety**: write operations are real account-level changes, requiring protection against unauthorized access, injection and duplication. Approach: authorization (cross-account/unauthorized interception) + security checks (prompt-injection detection, content review) + write control (only "confirm" triggers a change) + idempotency (trigger_key/executionId prevent duplicates; unknown-timeout reconciled via getTask/executionId instead of blind retry).
- **Impact:** AgentTask launched, giving Qingsong the ability to suspend and resume long-running tasks; the Ad Creation Agent was built from scratch.

#### 2. Smart Delivery Agent — In-flight Assisted Optimization --- Jul 2026 - Aug 2026

- **Background:** Traditional ad delivery relies on advertisers/optimizers manually watching the dashboard to decide replenishment, pausing and bid adjustment — labor-intensive, time-consuming, and lacking perception of marketplace and real-time data; current system adjustments have long relied on fixed rules and static thresholds without continuous reasoning, falling into a local-optimum solution pattern.
- **Goal:** Build an LLM-driven Smart Delivery Agent that upgrades in-flight decisions (replenishment / pausing / bid adjustment) from manual dashboard-watching and fixed rules to account-level dynamic decisions — perceiving marketplace and real-time data, forming a perceive-analyze-decide-execute-reflect continuous loop that maximizes spend under cost control.
- **Responsibilities (challenge + approach):**
  - **Multi-signal-driven in-flight decision**: infrastructure-volume / pausing / bid decisions need to fuse multi-source signals and marketplace/account-level data to be accurate, which fixed rules cannot adapt to. Approach: multi-signal perception (material creation / pausing / review failure / first spend) + marketplace data fusion (infrastructure volume and bid of top-10%-spend benchmark accounts in the same sub-industry) + account-level data (budget / balance / spend / exposure series), outputting infrastructure volume (campaign/ad-group/creative quota), pausing (non-scaling / over-cost) and bid (raise during cold-start, lower when the budget is reachable, hold during scaling).
  - **Bad-case accumulation & reflection**: decisions repeatedly hit two pitfalls — over-cost (overly aggressive bid) and non-scaling (overly conservative bid or insufficient infrastructure volume). Approach: accumulate operation-recalled bad cases as general experience, used as the reflection prompt for an extra pre-decision review, with monitoring fallback when the bid deviates from the average bid.
  - **Cost control**: 7.43M material-optimization calls/day make all-in on LLM uncontrollable in cost and latency. Approach: cost-trigger layering — invoke the LLM only at the low-frequency account-level infrastructure decision (not per material fill), plus semantic caching and small-model distillation.
- **Impact:** Material cold-start pass rate, scaling speed, non-duplicate material spend share, and material arpu improved (example, pending AB backfill); per-account daily token cost down ~60% vs. an all-in LLM approach
